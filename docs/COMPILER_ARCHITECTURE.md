# Архитектура компилятора `gorawc` и отказоустойчивость

Компилятор `gorawc` транслирует исходный код на языке Goraw в оптимизированный машинный код x86-64 через текстовый LLVM IR и компилятор/линкер `clang`.

---

## 1. Пайплайн компиляции

Пайплайн состоит из 7 последовательных этапов:

```text
[ Исходники .gw + .asm ]
           │
           ▼
1. Сборка графа модулей (gather_sources: рекурсивный импорт `import "..."`, устранение дубликатов)
           │
           ▼
2. Лексический анализ (lexer::Lexer: токенизация, строковые литералы, ключевые слова)
           │
           ▼
3. Синтаксический анализ (parser::Parser: AST, защита от зацикливания, синтаксические подсказки)
           │
           ▼
4. Сбор и проверка типов (types::collect: структуры, перечисления, сигнатуры функций)
           │
           ▼
5. Кодогенерация (codegen::Codegen: LLVM IR, встроенные интринзики, desugaring срезов и строк)
           │
           ▼
6. Компиляция внешнего ассемблера (gorawc::asm::assemble: трансляция вспомогательных .asm в .obj)
           │
           ▼
7. Финальная сборка и линковка (clang --target=x86_64-w64-windows-gnu -> исполняемый .exe)
```

---

## 2. Отказоустойчивость и защита от зацикливания (Anti-Loop Circuit Breaker)

В ходе разработки компиляторов частой катастрофической проблемой является зацикливание парсера при синтаксической ошибке пользователя (парсер падает в `synchronize()`, не сдвигает указатель токенов, генерирует миллионы ошибок и исчерпывает всю системную память, приводя к системному сбою/BSOD).

В `gorawc` внедрена 3-уровневая эшелонированная защита:

### 1. Circuit Breaker в парсере (`check_anti_loop`)
В [src/parser.rs](file:///P:/Goraw/src/parser.rs) встроен триггерный предохранитель:
- Парсер отслеживает индекс текущего токена `self.i`.
- Если на **одном и том же токене** происходит более 3 попыток обработки ошибки подряд без продвижения вперед, срабатывает аварийный трипвайр:
  ```rust
  if self.loop_count >= 3 {
      self.bump(); // принудительный сдвиг токена
      self.loop_count = 0;
  }
  ```
- Метод `synchronize()` гарантирует обязательное потребление токена-разделителя (`Tok::Semi`, `Tok::RBrace`) и продвижение вперед:
  ```rust
  if self.i == prev_i && !self.at_eof() {
      self.bump();
  }
  ```

### 2. Жесткий потолок диагностик (`MAX_DIAGNOSTICS_CAP = 50`)
В модуле [src/diag.rs](file:///P:/Goraw/src/diag.rs) установлен аппаратный предел:
- Буфер `Diags::push()` прекращает аллокацию новых диагностических сообщений при достижении **50 ошибок**.
- Это исключает экспоненциальное раздувание памяти строками и векторами при синтаксическом мусоре во входном файле.

### 3. Специализированный разбор опечаток сигнатур (`E0028`)
Вместо каскада непонятных грамматических ошибок парсер распознает типичные опечатки программистов:
- `fn main(): i32`
- `fn main() > i32`
- `fn main() => i32`
При их обнаружении парсер сразу выдает диагностику `E0028` с конкретным предложением замены на `-> i32` и плавно продолжает разбор тела функции.

## 3. Двойная система диагностики (Human + LLM-JSON)

Goraw спроектирован для бесшовной работы как с людьми, так и с языковыми моделями.

### Человекочитаемый вывод (по умолчанию)
Выводит контекстную подсветку места ошибки, подчеркивание символов и подсказки по исправлению:
```text
error[E0028]: для возвращаемого типа функции используется `->`, а не `:`
  --> examples/broken.gw:1:11
   | fn main(): i32 {
   |          ^
   = hint: замените на `fn main() -> i32`

1 error(s), 0 warning(s)
```

### Машиночитаемый формат (`--json`)
Флаг `--json` выводит строгий JSON-массив ошибок внутри XML-тегов `<diagnostics>`:
```json
<diagnostics>
[
  {
    "code": "E0028",
    "severity": "error",
    "span": {
      "file": "examples/broken.gw",
      "start": { "line": 1, "col": 11, "offset": 10 },
      "end": { "line": 1, "col": 12, "offset": 11 }
    },
    "message": "для возвращаемого типа функции используется `->`, а не `:`",
    "hints": [
      "замените на `fn main() -> i32`"
    ]
  }
]
</diagnostics>
```
Это позволяет AI-агентам детерминированно парсить ошибки регулярными выражениями без двусмысленностей.

## 4. JIT-подсистема

Когда в программе используется выражение `jit(args) { body }`, компилятор:
1. Выделяет тело `jit` в изолированный LLVM-модуль.
2. Генерирует вызов рантайм-компилятора `@goraw_jit_compile(...)`.
3. Автоматически разворачивает рядом рантайм-файл [goraw_jit.c](file:///P:/Goraw/runtime/goraw_jit.c), реализующий кэширование указателей на функции и интеграцию с LLVM ExecutionEngine / ORC JIT.
4. Прозрачно линкует `goraw_jit.c` вместе с основным бинарником.
