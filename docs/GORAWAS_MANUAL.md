# Руководство по нативному ассемблеру `gorawas` (Goraw-asm)

`gorawas` — нативный ассемблер x86-64 для собственного Intel-диалекта **Goraw-asm**.

---

## 1. Архитектура и принципы

Ассемблер разработан по чистой схеме (clean-room):
- **Собственный фронтенд**: лексер, парсер диалекта, поддержка секций (`.text`, `.data`, `.rdata`), директив данных (`db`..`dq`) и таблица символов написаны внутри проекта.
- **Единая диагностика**: ассемблер использует общий компиляторный модуль диагностики ([src/diag.rs](file:///P:/Goraw/src/diag.rs)), выдавая как человекочитаемые ошибки с визуализацией строк, так и структурированный JSON для LLM (`--json`).
- **Проверенное кодирование**: энкодинг сложных инструкций x86-64 (ModRM, SIB, REX-префиксы) делегирован крейту `iced-x86`.
- **Запись объектных файлов**: генерация стандартных COFF-файлов Windows (`.obj`) и расчет таблиц релокаций (`IMAGE_REL_AMD64_REL32`) выполняются через крейт `object`.

## 2. Формат файлов и синтаксис

### Комментарии и метки
```nasm
; Это комментарий до конца строки

my_label:               ; Метка на отдельной строке
main: sub rsp, 40       ; Метка на одной строке с инструкцией
msg:  db "Hello", 0     ; Метка перед данными
```

### Секции
- `section .text` (или `segment .text`) — секция исполняемого машинного кода.
- `section .data` — секция инициализированных изменяемых данных (Read-Write).
- `section .rdata` (алиас `.rodata`) — секция констант и строк только для чтения (Read-Only).

### Экспорт и импорт символов
- `global <name>` (или `globl`) — экспорт символа в таблицу экспорта COFF (`SymbolScope::Linkage`). Может содержать несколько символов через запятую: `global foo, bar`.
- `extern <name>` (или `extrn`) — импорт внешнего символа из CRT или других объектных библиотек (например, `extern printf, puts, malloc`).
- `default rel` — поддерживаемая директива NASM-совместимости, указывающая на преимущественное использование RIP-relative адресации.

## 3. Директивы определения данных

`gorawas` поддерживает четыре директивы размещения данных в секциях `.data` и `.rdata`:

| Директива | Размер элемента | Поддерживаемые значения |
|---|---|---|
| `db` | 1 байт (8 бит) | Числа (0..255, -128..127), ASCII и UTF-8 строки в кавычках |
| `dw` | 2 байта (16 бит) | 16-битные целые (little-endian) |
| `dd` | 4 байта (32 бита) | 32-битные целые (little-endian) |
| `dq` | 8 байт (64 бита) | 64-битные целые (little-endian) |

### Разбор строк и escape-последовательностей
Директива `db` полноценно поддерживает строки с escape-последовательностями:
- `\n` — перевод строки (0x0A)
- `\r` — возврат каретки (0x0D)
- `\t` — табуляция (0x09)
- `\0` — нулевой терминатор (0x00)
- `\"` — символ кавычки
- `\\` — обратный слеш

Пример:
```nasm
section .rdata
hello_msg:
    db "Привет, Goraw-asm!\n", 0

section .data
primes:
    dd 2, 3, 5, 7, 11, 13
lookup_table:
    dq 0x1000, 0x2000, 0x4000, 0x8000
```

## 4. Регистры и адресация памяти

### Регистры
- **64-битные**: `rax`, `rbx`, `rcx`, `rdx`, `rsi`, `rdi`, `rbp`, `rsp`, `r8`, `r9`, `r10`, `r11`, `r12`, `r13`, `r14`, `r15`.
- **32-битные**: `eax`, `ebx`, `ecx`, `edx`, `esi`, `edi`, `ebp`, `esp`, `r8d`, `r9d`, `r10d`, `r11d`, `r12d`, `r13d`, `r14d`, `r15d`.

### Непосредственные значения (Immediate)
- Десятичные: `42`, `-10`, `1_000_000` (разрешены разделители `_`).
- Шестнадцатеричные: `0x2A`, `0XFFFF_FFFF`.
- Двоичные: `0b101010`, `0B1111_0000`.

### Адресация памяти
1. **Базовая адресация**:
   ```nasm
   mov rax, [rcx]           ; загрузка qword по адресу rcx
   mov [rdx], rax           ; сохранение qword
   ```
2. **База + смещение**:
   ```nasm
   mov rax, [rcx + 16]
   mov rax, [rcx - 8]
   ```
3. **База + индекс * масштаб + смещение**:
   ```nasm
   mov rax, [rcx + rdx*8 + 32]
   lea rbx, [rdi + rsi*4]
   ```
4. **RIP-Relative адресация к меткам данных**:
   Поддерживаются три эквивалентные формы:
   ```nasm
   lea rcx, [rip + hello_msg]   ; каноническая x86-64
   lea rcx, [rel hello_msg]     ; NASM-стиль
   lea rcx, [hello_msg]         ; короткая форма
   ```
   Ассемблер автоматически формирует 7-байтную инструкцию с опкодом `48 8d 05 [rel32]` и регистрирует релокацию `IMAGE_REL_AMD64_REL32`.

## 5. Таблица инструкций

### Управление потоком (Ветвления и вызовы)
| Мнемоника | Описание | Поддерживаемые цели |
|---|---|---|
| `jmp` | Безусловный переход | Внутренняя метка, регистр `r64`, внешний символ (`extern`) |
| `call` | Вызов функции | Внутренняя метка, регистр `r64`, внешний символ (`extern`) |
| `je` / `jz` | Переход, если равно / ноль | Внутренняя метка |
| `jne` / `jnz`| Переход, если не равно / не ноль | Внутренняя метка |
| `jl` / `jle` | Знаковое меньше / меньше или равно | Внутренняя метка |
| `jg` / `jge` | Знаковое больше / больше или равно | Внутренняя метка |
| `ja` / `jae` | Беззнаковое выше / выше или равно | Внутренняя метка |
| `jb` / `jbe` | Беззнаковое ниже / ниже или равно | Внутренняя метка |
| `js` / `jns` | По знаку (SF=1 / SF=0) | Внутренняя метка |
| `loop` | Цикл со счетчиком `rcx` | Внутренняя метка |
| `ret` | Возврат из функции | — |

### Пересылка данных
| Инструкция | Формы операндов |
|---|---|
| `mov` | `(r64, r64)`, `(r64, imm)`, `(r32, r32)`, `(r32, imm)`, `(r64, [mem])`, `([mem], r64)`, `([mem], imm)`, `(r64, [rip + sym])`, `([rip + sym], r64)`, `(r32, [rip + sym])`, `([rip + sym], r32)` |
| `lea` | `(r64, [mem])`, `(r64, [rip + sym])` |
| `push` / `pop` | `(r64)` |

### Арифметика и логика (ALU)
| Инструкция | Формы операндов |
|---|---|
| `add`, `sub` | `(r64, r64)`, `(r64, imm)`, `(r32, r32)`, `(r32, imm)`, `(r64, [mem])`, `([mem], r64)` |
| `and`, `or`, `xor` | `(r64, r64)`, `(r64, imm)`, `(r32, r32)`, `(r32, imm)`, `(r64, [mem])` |
| `cmp` | `(r64, r64)`, `(r64, imm)`, `(r32, r32)`, `(r32, imm)`, `(r64, [mem])`, `([mem], r64)` |
| `inc`, `dec` | `(r64)`, `(r32)` |
| `neg`, `not` | `(r64)` |
| `imul` | `(r64, r64)`, `(r64, [mem])` |
| `cqo` | Расширение RAX в RDX:RAX |

### Системные инструкции
- `syscall` — системный вызов x86-64
- `nop` — холостая операция
- `leave` — восстановление стекового кадра (mov rsp, rbp + pop rbp)

## 6. Windows x64 ABI (Соглашение о вызовах)

При написании функций для вызова из Goraw или CRT необходимо соблюдать соглашение Microsoft x64:

1. **Регистры аргументов**:
   - 1-й аргумент: `rcx` (или `ecx`)
   - 2-й аргумент: `rdx` (или `edx`)
   - 3-й аргумент: `r8` (или `r8d`)
   - 4-й аргумент: `r9` (или `r9d`)
   - Возвращаемое значение: `rax` (или `eax`)
2. **Shadow Space**:
   - Вызывающая сторона обязана выделить 32 байта теневого стека перед любым `call`:
     ```nasm
     sub rsp, 40       ; 32 байта shadow space + 8 байт для выравнивания стека по 16 байт
     call printf
     add rsp, 40
     ```
3. **Сохраняемые регистры (Callee-saved)**:
   - `rbx`, `rbp`, `rdi`, `rsi`, `r12`, `r13`, `r14`, `r15`. Если функция их изменяет, она обязана сохранить их в стек и восстановить перед `ret`.

## 7. Полные практические примеры

### Пример 1: Автономная программа с вызовом CRT printf
Файл [examples/native_hello.asm](file:///P:/Goraw/examples/native_hello.asm):

```nasm
default rel

section .rdata
msg:
    db "Hello from native Goraw-asm with external relocations and .rdata!", 10, 0

section .text
extern printf
global main

main:
    sub rsp, 40
    lea rcx, [rip + msg]
    call printf
    add rsp, 40
    xor eax, eax
    ret
```

Сборка и запуск:
```bash
.\box.cmd gorawas examples\native_hello.asm -o examples\native_hello.obj
clang --target=x86_64-pc-windows-gnu examples\native_hello.obj -o hello.exe
.\hello.exe
```

### Пример 2: Интеграция с компилятором `gorawc`

Ассемблерный файл [examples/native_greet.asm](file:///P:/Goraw/examples/native_greet.asm):
```nasm
default rel

section .rdata
greeting:
    db "Greeting from Goraw-asm called by Goraw language!", 10, 0

section .text
extern printf
global goraw_greet

goraw_greet:
    sub rsp, 40
    lea rcx, [rip + greeting]
    call printf
    add rsp, 40
    ret
```

Goraw файл [examples/native_greet_main.gw](file:///P:/Goraw/examples/native_greet_main.gw):
```goraw
extern fn goraw_greet();

fn main() -> i32 {
    goraw_greet();
    println("SUCCESS: goraw language called gorawas native assembly with extern relocations!");
    return 0;
}
```

Сборка и запуск одной командой через `gorawc`:
```bash
.\box.cmd gorawc examples\native_greet_main.gw examples\native_greet.asm --run
```
Компилятор сам на лету собирает `.asm` через `gorawas`, компонует с кодом Goraw и запускает бинарник.
